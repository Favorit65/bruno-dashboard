# Дашборд обслуживания объектов — MVP

Прототип дашборда для операционной аналитики Bruno. Работает в двух режимах:

- **`dashboard_v3.html`** — на синтетических данных, ничего не нужно устанавливать. Двойной клик → открывается в браузере. Используйте как fallback на презентации, если что-то не сложится с API.
- **`dashboard_live.html`** — на реальных данных из Bruno API через промежуточный `data.json` (сформированный скриптом `extract.py`).

Оба HTML идентичны по функциональности — отличается только источник данных.

## Быстрый старт (Windows)

### 1. Установка Python

Скачайте установщик с [python.org/downloads](https://www.python.org/downloads/) (версия 3.9+).

**Важно:** на первом экране установщика поставьте галочку **«Add Python to PATH»**, иначе `python` не будет запускаться из командной строки.

Проверка после установки — откройте **PowerShell** (Win+X → Terminal или PowerShell) и выполните:

```powershell
python --version
```

Должно показать что-то вроде `Python 3.12.0`.

### 2. Установка зависимости `requests`

В той же PowerShell:

```powershell
pip install requests
```

### 3. Выгрузка данных из Bruno API

Откройте PowerShell в папке с файлами (Shift + правый клик по папке → «Открыть в терминале»), затем:

```powershell
python extract.py --token ВАШ_JWT_ТОКЕН --from 2025-01-01 --to 2026-07-02
```

Скрипт покажет прогресс по каждому ресурсу:

```
→ object…
  [object] стр 1: 15/15
→ zone…
  [zone] стр 1: 87/87
→ feedback…
  [feedback] стр 1: 500/7842
  [feedback] стр 2: 1000/7842
  ...
→ taskPlan…
  ...
```

По завершении рядом с `extract.py` появится файл `data.json` (объём зависит от количества данных — ожидайте от нескольких МБ до 100+ МБ).

### 4. Открытие дашборда

**Тут есть подводный камень:** Chrome/Edge/Firefox блокируют `fetch()` к локальным файлам при открытии HTML через `file://`. Поэтому двойной клик по `dashboard_live.html` покажет красную ошибку.

Решение — запустить одну команду в той же PowerShell:

```powershell
python -m http.server 8000
```

После этого откройте в браузере: **http://localhost:8000/dashboard_live.html**

Всё, дашборд загрузится с реальными данными. Пока PowerShell открыт — сервер работает.

Чтобы остановить сервер — вернитесь в PowerShell и нажмите `Ctrl+C`.

## Полный список опций `extract.py`

```powershell
python extract.py --help
```

Полезные:

| Опция | Что делает |
|---|---|
| `--dry-run` | только проверить токен и права, без выгрузки |
| `--out my.json` | сохранить в другой файл |
| `--skip surveyResult` | не тянуть какой-то ресурс (можно указать несколько раз) |
| `--pause-ms 300` | увеличить паузу между запросами при 429-ошибках |
| `--page-limit 200` | уменьшить размер страницы (по умолчанию 500) |

Пример:

```powershell
python extract.py --token XXX --from 2025-01-01 --to 2026-07-02 --skip surveyResult --pause-ms 200
```

## Типовые ошибки

**`ERROR: не установлен пакет 'requests'`** — выполните `pip install requests`.

**`401 Unauthorized`** — токен неверный или истёк. Возьмите свежий в панели Bruno.

**`403 Forbidden` на каком-то ресурсе** — у токена нет прав `read` на этот ресурс. Скрипт пропустит его и продолжит; в дашборде соответствующий блок будет пустым. Проверьте настройки токена.

**`404 Not Found` на всех эндпоинтах** — возможно, base URL API изменился. Проверьте, что для вашего проекта он действительно `https://api.brunosystem.ru`, и если нет — сообщите, я поправлю.

**Красный баннер в дашборде «Не удалось загрузить data.json»** — либо файла нет (сначала запустите extract.py), либо HTML открыт через `file://` (запустите `python -m http.server 8000`).

**Пустой дашборд с нулями** — данные загрузились, но за выбранный период их нет. Проверьте фильтр периода наверху (по умолчанию отображается диапазон из `meta.period` в data.json).

**Дашборд загрузился, но `feedback` = 0** — возможно, у ресурса `feedback` в вашем API поле даты называется не `date`. Откройте DevTools (F12) → Console — там должна быть строка `mapped: {...}` с количеством по каждому ресурсу. Если проблема с датой — сообщите точное имя поля из вашего API, поправлю маппер за 2 минуты.

## Что дальше

Как только вы посмотрите на реальные данные, скорее всего понадобится доделать:

- **Мэппинг полей.** Я угадал имена полей `feedback`/`remark` по документации, но точные названия дат/ID могу знать неточно. Если что — открывайте `data.json` в блокноте, ищите в блоке `"feedback": [{...}]` реальные поля и пришлите мне пример — обновлю маппер.
- **Формулы эффективности и SLA** — сейчас захардкожены (см. заголовки блоков). После просмотра реальных чисел, вероятно, захотите подкрутить пороги.
- **Фильтр периода** — если данных много лет, добавим годовые пресеты.
- **Кэш** — если данных стало 100+ МБ, стоит перевести data.json на MessagePack или GZIP (уменьшит в 5-10 раз).
