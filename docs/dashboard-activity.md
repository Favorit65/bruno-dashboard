# Дашборд: фактическое выполнение и окно задания

Версия от 3 ноября 2026 года.

- Ежедневные задания: `deactivationDate - date <= 24 часа`. Пролонгированные: больше 24 часов. `activationDate` и ранний допуск не увеличивают окно.
- Выполнено: исходный `COMPLETED` и заполненный фактический `employeeID`. День и час — `date_complete` по Москве. `completionDate` является плановым временем и не используется как фактическое.
- Остальные статусы сохраняют дату задания `dateLocal`. Это срез текущих статусов, а не история переходов. Пропущено — только исходный `MISSED`.
- Эффективность ежедневных: выполнено / (выполнено + пропущено). Пролонгированных: выполнено / (выполнено + пропущено + WAITING). Нулевой знаменатель — отсутствующее значение.
- Глобальный переключатель окна применяется к разделам, детализации и CSV. Чекбоксы пяти статусов меняют только видимость рядов первого графика; формула эффективности от них не зависит.
- Таблицы и CSV содержат отдельные строки по дням периода. Каждое командное задание учитывается один раз; задание без конкретного ответственного не распределяется по участникам команды.

`byActivity` — новый компактный куб в core (stride 27). Старые кубы сохранены для существующих отчётов. Обе части модели и `model.version.json` связаны одним buildId. Интерфейс требует модель с `activityVersion: 1` и сохраняет предыдущую загруженную модель при неудачном обновлении.

Проверки:

```text
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/dashboard.test.cjs tests/refresh.test.cjs tests/work.test.cjs tests/activity.test.cjs
```

В изолированном пилоте дополнительно выполнена независимая сверка всех дат по пяти доступным объектам с исходными заданиями; контрольная неделя 26.10–01.11 не содержит повторных ID. Сырые данные и локальные модели не включены в этот коммит.
