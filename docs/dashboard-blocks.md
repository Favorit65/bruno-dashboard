# Как считаются показатели Bruno Dashboard

Версия для ревью от 5 ноября 2026 года. Локальный срез: данные до 02.11 02:28 МСК, buildId 2026-11-03T08:24:56.316742+00:00.

## Общие правила

Дашборд на Pages читает индекс сборки и только недели выбранного периода. Почасовой файл загружается при переходе к часам, тексты обращений — при открытии реестра. Ссылка с фильтрами восстанавливает тот же период и представление. Файлы проверяются по идентификатору сборки. Если загрузка прерывается, интерфейс предлагает повторить запрос. Полная модель сохраняется для конвейера отчётности.

По умолчанию выбран период с понедельника до сегодняшнего дня по Москве и пять доступных объектов. Переключатель длительности использует интервал от планового начала задания до последнего допустимого старта. До 24 часов включительно — ежедневное задание, свыше 24 часов — пролонгированное. Неопределённое окно не входит в эти режимы.

Выполнение учитывается в день и час фактического завершения по Москве при статусе COMPLETED, наличии исполнителя и времени завершения. Пропуск учитывается только по статусу MISSED. У пропущенных, новых, ожидающих и выполняемых заданий день берётся из расписания. Поэтому график показывает последние известные состояния заданий, распределённые по датам. Для обращения как самостоятельной единицы используется время его регистрации.

Обозначим выполненные задания В, пропущенные П, ожидающие О. Эффективность ежедневных равна В / (В + П), пролонгированных — В / (В + П + О). При нулевом знаменателе показан прочерк. Процент по группе рассчитывается по суммарным количествам.

| Блок на экране | Что попадает в расчёт | Как проверить |
|---|---|---|
| Задачи по статусам во времени | Каждый день, час или более крупный интервал содержит пять отдельных счётчиков. Карточка «Всего» складывает все пять. Галочки управляют видимостью рядов. | Сумма пяти колонок дневной таблицы равна «Всего». Включение дополнительной галочки сохраняет эффективность. |

Процент изменения объёма, выполнений и пропусков сравнивает начало последнего месяца архива и те же числа предыдущего месяца. Остальные фильтры учитываются. | При чтении недельного числа и стрелки нужно учитывать, что у них разные периоды. Месяц с неопределённой эффективностью даёт разрыв в линии. |
| Категории задач | Задание с taskID относится к плановым, остальные к неплановым. Дерево показывает обе категории по выбранному периоду, объектам, функциям и окну. Доля категории равна её объёму / объёму обеих категорий. | Щелчок по узлу применяет категорию к остальным блокам, которые её поддерживают. |
| Обращения по объектам | Один feedbackID учитывается один раз по московскому времени регистрации. Режим «Неплановые задачи» считает по дате активности все задания без taskID, включая созданные вручную. | В режиме обращений число строк реестра равно карточке «Обращений» и сумме столбцов за период. У блока собственный переключатель источника. |
| Реестр обращений и CSV | Одна строка содержит дату и время регистрации, объект, этаж, зону, «Выполнено», исполнителей и текст. Этаж берётся из иерархии зоны. «Да» требует подтверждённого выполнения **всех** связанных заданий, включая задания других функций и длительностей. Если выполнены все — «Да», ни одного из трёх — «0/3», без заданий — прочерк. Контакты в тексте маскируются при сборке. |
| Воронка и полоса статусов | В режиме обращений единица воронки — связанное задание обращений, зарегистрированных в периоде. Во втором режиме — неплановое задание по дате активности. Этапы равны всем пяти статусам, затем сумме В + П + выполняемые, затем В + выполняемые, затем В. Конверсия на стрелке делит этап на предыдущий. Полоса объединяет NEW и WAITING в ожидание и отдельно показывает выполняемые, завершённые и пропущенные. | П входит в «Вышли из ожидания». Строки детализации распределяют выполнения и пропуски между исполнителями и командами. | Суммы выполнений и пропусков в детализации функции должны совпасть с её карточкой. ## Обновление

GitHub Actions запрашивает запуск в 17-ю минуту каждого часа. В обычном проходе выгружаются последние дни и старые задания с действующими окнами. Расширенная сверка догоняет первый доступный запуск после 02:00 МСК. При ошибке загрузки суток сборка останавливается до публикации неполного результата. На странице время «Данные от» относится к источнику. Кнопка «Обновить данные» загружает опубликованную модель в браузер, а «Журнал обновлений» ведёт к запускам GitHub.

Таймер открытой вкладки проверяет опубликованную модель раз в час и при возвращении после перерыва. Время фактической публикации зависит от того, когда GitHub запустил процесс и когда закончилась загрузка и сборка.


## Действие фильтров

Обозначения: П — выбранный период (включая обе даты, МСК), О — выбранные доступные объекты, Ф — функции, Д — ежедневные/пролонгированные, К — все/плановые/неплановые.

| Блок | Действующие фильтры | Особенности |
|---|---|---|
| Статусы, крупные KPI | П, О, Ф, Д, К | Чекбоксы скрывают ряды, а не задания в KPI и эффективности. Детализация графика меняет группировку, переход в день сужает общий период. |
| Мини-графики KPI | О, Ф, Д, К | Последние шесть месяцев архива, независимо от П. Стрелка: (текущий объём − предыдущий) / предыдущий; при предыдущем 0 — прочерк. Сравниваются 1..N последнего месяца архива и 1..N предыдущего в пределах существующих дат. |
| Категории | П, О, Ф, Д | К выбирается кликом по категории; само дерево сохраняет обе категории. |
| Обращения и реестр | П по регистрации, О, Ф, Д | Ф и Д проверяют наличие хотя бы одного подходящего задания. К не ограничивает обращения. Статус строки и исполнители считаются по всем заданиям обращения. |
| Воронка обращений | П по регистрации, О, Ф, Д | Считает только связанные задания выбранных Ф и Д у обращений периода; К не действует. |
| Неплановые задачи и их воронка | П по активности, О, Ф, Д | Собственный источник «Неплановые задачи» фиксирует неплановые независимо от К. Это включает ручные задания без обращения. |
| Функции, выработка, объекты/зоны, персонал | П, О, Ф, Д, К | Разрезы используют одну модель активности. Зоны дополнительно ограничены выбранным объектом. Персонал включает только известного фактического исполнителя либо единственного известного назначенного сотрудника. |
| План–факт | П, О, Ф, Д | Фиксирует плановые независимо от К; отмечено в интерфейсе. |
| Замечания и качество | Нет численных расчётов | Модули недоступны, нули не подставляются. |

Таблицы и CSV показывают посуточную детализацию выбранного периода, реестр — строки обращений. CSV сохраняет текущую сортировку таблицы; текстовые ячейки с потенциальными формулами экранируются. Снятые все объекты или функции означают пустой срез; сброс возвращает полный доступный набор. Ссылка сохраняет фильтры, включая пустой выбор функций.

## Ограничения интерпретации

- Данные — последние известные состояния, без истории переходов. Пропуск не доказывает начало работы.
- Источник реестра — обращения, найденные в taskPlan. Если модель содержит обращение без заданий, при общем выборе функций реестр показывает его с прочерком. Обращения без созданных заданий пока отсутствуют в taskPlan.
- Сотрудник в нескольких функциях — несколько наблюдений распределения эффективности, один человек в карточке численности. Для сотрудника без знаменателя эффективность не определена, в гистограмму он не входит.
- Численность — активные учётки активных команд на снимок справочников. «Домашний» объект команды выбирается по наибольшему числу её заданий за весь архив; это расчётная привязка, не HR-штат по объектам. Внутри пары объект/функция учётки уникальны, общий итог складывает пары. Неоднозначная функция остаётся отдельной группой.
- Время «Данные от» — максимум fetchedAt успешно загруженных суток; оно не означает одновременную перевыгрузку всей истории.
- Нет срока завершения — выполнение учитывается, но не классифицируется как вовремя/поздно. Нет фактической даты или исполнителя — выполнение не подтверждено.
