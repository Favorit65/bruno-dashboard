# Планировщик поручений — развёртывание

Всё делается в браузере: Google Таблицы, редактор Apps Script и веб-интерфейс GitHub.
Терминал не нужен. Время — около 20 минут.

Что получится: Google Таблица (база данных) + скрипт Apps Script (сервер API,
права, письма) + страница `planner.html` на GitHub Pages рядом с дашбордом.

> Перед началом: изменения из этой ветки должны быть в `main` и опубликованы
> (вкладка **Actions** → «Публикация дашборда» завершилась зелёным). Проверка —
> открывается `https://favorit65.github.io/bruno-dashboard/planner.html?demo=1`.

---

## 1. Создать таблицу

1. Откройте <https://sheets.new> под тем Google-аккаунтом, от имени которого будет
   работать планировщик (все записи и письма пойдут от него).
2. Назовите таблицу, например «Поручения отдела».

Таблица — это и есть база. Доступ к ней дайте только модераторам: сотрудники
работают через сайт, таблица им не нужна.

## 2. Вставить код Apps Script

1. В таблице: **Расширения → Apps Script**. Откроется редактор с файлом `Код.gs` / `Code.gs`.
2. В репозитории на GitHub откройте `apps-script/Code.gs` → кнопка **Raw** (или значок
   «Copy raw file») → скопируйте всё.
3. В редакторе выделите всё в `Code.gs` (Ctrl+A) и вставьте скопированное.
4. Слева у «Файлы» нажмите **+ → Скрипт**, назовите `Core` (расширение `.gs`
   добавится само) и вставьте содержимое `apps-script/Core.gs`.
5. Так же создайте скрипт `Status` и вставьте `apps-script/Status.gs`.
6. Манифест: **⚙ Настройки проекта** → включите «Показывать файл манифеста
   appsscript.json в редакторе». Вернитесь в **Редактор**, откройте `appsscript.json`
   и замените содержимое на `apps-script/appsscript.json`.
7. Нажмите **💾 Сохранить проект** (Ctrl+S).

Итого в проекте четыре файла: `Code.gs`, `Core.gs`, `Status.gs`, `appsscript.json`.
Порядок файлов в списке не важен.

## 3. Запустить `setup()`, затем `seedDemo()`

1. Вверху редактора в списке функций выберите **setup** → **Выполнить**.
2. Google попросит разрешения: **Проверить разрешения** → выберите аккаунт →
   «Google не проверял это приложение» → **Дополнительные настройки** →
   **Перейти на страницу проекта (небезопасно)** → **Разрешить**.
   Это ваш собственный скрипт; разрешения нужны на таблицу, почту, Диск (резервные
   копии) и внешние запросы (загрузка демо-данных).
3. В журнале выполнения появится «Готово: листы Tasks, Checklist, Activity, Users,
   Folders, Settings». В таблице появились эти листы, в Folders — шесть стартовых
   папок (ПДР, РМТ, ОБК, ВНД, ОТЧ, ОРГ).
4. **Демо-данные (по желанию, для пробы):** выберите **seedDemo** → **Выполнить**.
   Загрузятся 8 поручений прототипа и 6 условных пользователей (`head`, `mod`,
   `kom`, `clean`, `mms`, `pdr`). Работает только на пустом листе Tasks.
   Для рабочего запуска этот шаг пропустите или потом удалите строки демо руками.
5. Откройте лист **Settings** и проверьте `planner_url` — адрес `planner.html` на
   Pages (по умолчанию `https://favorit65.github.io/bruno-dashboard/planner.html`).
   Из него собираются персональные ссылки и ссылки в письмах.

`setup()` можно запускать повторно: он только добавляет недостающие листы и колонки.

## 4. Развернуть → Веб-приложение, скопировать URL

1. В редакторе: **Развернуть → Новое развёртывание**.
2. Шестерёнка у «Выберите тип» → **Веб-приложение**.
3. Описание — любое, например «Планировщик v1».
4. **Выполнять от имени: Я** (ваш аккаунт).
5. **У кого есть доступ: Все** (Anyone). Без входа в Google — сотрудники
   авторизуются персональным ключом, а без ключа сервер ничего не отдаёт.
6. **Развернуть** → скопируйте **URL веб-приложения** (оканчивается на `/exec`).
7. Проверка: откройте этот URL в браузере — должно показать
   `{"ok":true,"service":"bruno-planner",…}`.

**Обновление кода потом:** вставили новый код → **Развернуть → Управление
развёртываниями** → карандаш → «Версия: Новая версия» → **Развернуть**. URL
останется прежним, менять `planner.html` не нужно. («Новое развёртывание» выдаст
новый URL — так делать не надо.)

## 5. Вставить URL в `API_URL` в `planner.html` (веб-GitHub)

1. На GitHub откройте `planner.html` → значок карандаша **Edit this file**.
2. Найдите (Ctrl+F) строку `const API_URL='';` (в начале скрипта, под блоком «НАСТРОЙКА»).
3. Вставьте URL между кавычками: `const API_URL='https://script.google.com/macros/s/…/exec';`
4. **Commit changes…** → в `main` → **Commit changes**.
5. Вкладка **Actions** → дождитесь зелёной «Публикация дашборда» (1–2 мин).

URL не секрет: он виден любому, кто откроет страницу, но без персонального ключа
сервер отвечает только «Нужна персональная ссылка».

## 6. Завести людей и выдать ключи через `issueKey()`

1. Лист **Users**, по строке на человека:

   | Колонка | Что писать |
   |---|---|
   | `id` | короткий латинский код без пробелов: `ivanov`, `head` — не меняется |
   | `name` | как показывать в интерфейсе: «Иванов И. И.» или должность |
   | `handle` | ник для @упоминаний, одним словом: `Иванов`, `Комендант_Б` |
   | `role` | `head` руководитель · `mod` модератор · `owner` ответственный · `observer` наблюдатель |
   | `position` | должность (необязательно) |
   | `email` | почта для писем (необязательно; пусто — писем нет) |
   | `bruno_employee_id` | ID сотрудника в Bruno (UUID из справочника сотрудников; нужен только для «Передать в Bruno»; можно пусто) |
   | `active` | `TRUE` |
   | `key_hash`, `last_read_ts`, `objects` | не заполнять |

2. Обновите вкладку с таблицей — появится меню **Планировщик**.
3. **Планировщик → Выдать ключ…** → введите `id` пользователя → **ОК**.
   Откроется окно с персональной ссылкой вида `…/planner.html#k=…` — **она показывается
   один раз**. Скопируйте и передайте человеку лично (мессенджер, письмо).
   В таблице сохраняется только хэш ключа (`key_hash`), сам ключ нигде не хранится.
4. Потерял ссылку — снова «Выдать ключ…»: старая сразу перестанет работать.
   Уволился — **Планировщик → Отозвать ключ…** или `active` = `FALSE`.

Без меню, из редактора: впишите id в `var KEY_USER_ID = 'ivanov';` вверху `Code.gs`,
выберите функцию `issueKey` (или `revokeKey`) → **Выполнить**; ссылка будет в журнале
выполнения. После — верните `KEY_USER_ID = ''`.

Папки меняет модератор прямо в листе **Folders** (`active` = `FALSE` — скрыть).
Колонку `counters_json` не трогайте: в ней счётчики кодов `ПАПКА-ГГ-NNN`.

## 7. Проверить

1. Откройте свою ссылку с ключом: загрузится таймлайн, справа вверху «Я — …».
   Ключ сохранится в браузере и исчезнет из адресной строки.
2. Создайте поручение (кнопка «+ Поручение» видна руководителю и модератору): в
   листе **Tasks** появилась строка с кодом вида `ПДР-26-001`, в **Checklist** —
   пункты, в **Activity** — события «создал(а)», «назначил(а)».
3. Откройте ссылку ответственного на телефоне → «Мои задачи» → отметьте пункт:
   у пункта появятся имя и время, в **Checklist** — `done_by`, `done_at`.
4. Комментарий с `@ником` — упомянутому с заполненным `email` придёт письмо.
5. Два окна на одной задаче: в одном перенесите срок, в другом поставьте блокер —
   второе покажет «Задачу изменили, обновите», ничего не потеряется.
6. **Планировщик → Включить резервное копирование и пересчёт статусов** — по
   понедельникам копия таблицы в папку «Планировщик — резервные копии» на Диске,
   ежедневно в 5:00 обновляется колонка `status` (снимок для чтения людьми;
   интерфейс считает статус сам).

Демо без бэкенда всегда доступно: `planner.html?demo=1`.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| «Планировщик ещё не подключён к таблице» | В `planner.html` пустой `API_URL` — шаг 5 |
| «Ключ не действует» | Ключ перевыпущен/отозван или `active` ≠ `TRUE` — выдать заново |
| «Сервер ответил не JSON» | Развёртывание с доступом не «Все» или URL не `/exec` — шаг 4 |
| «Нет листа … Запустите setup()» | Лист переименован или удалён — запустите `setup()` |
| «Сервер занят, повторите» | Одновременных записей больше, чем успевает обработать блокировка (20 с) |
| Письма не приходят | Нет `email` в Users, `mail_enabled` = `FALSE` в Settings или исчерпана дневная квота (журнал выполнения: «Квота писем…») |
| Новый код не работает | Обновили код, но не выпустили «Новую версию» развёртывания — см. шаг 4 |

## Ограничения Apps Script

- Каждый запрос — 0,5–2 с. Интерфейс показывает изменение сразу и сохраняет в фоне
  (индикатор «Сохранение… / Сохранено»); при ошибке изменение откатывается.
- Изменения одного пользователя отправляются по очереди; все записи сервера идут
  под общей блокировкой — одновременно пишет один запрос.
- Письма: ~100 в день на обычном аккаунте Google, 1500 — на Workspace. Перед
  отправкой проверяется остаток квоты; при нуле действие выполняется, письмо — нет.
- Одно выполнение ≤ 6 мин (с запасом для объёма ТЗ: до 500 задач, 20 человек).
- Лента в интерфейсе — последние 300 событий; полная история — в листе Activity.
