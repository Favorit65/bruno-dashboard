# Планировщик — развёртывание новой архитектуры

Локальная рабочая редакция обновлена 05.11.2026. Пройдены 80 целевых автоматических тестов на локальных имитациях. Развёртывание и доставка реальных писем не выполнялись.

## Изменения

Один руководитель; руководитель и модератор имеют одинаковые права управления и приёмки. Ответственный выбирается по типу, затем по имени. В Users: head — руководитель, owner с subtype admin/commandant/inspector — администратор/комендант/обходчик, mod с subtype moderator — модератор.

Ответственный видит цель целиком, если назначен хотя бы на одну подзадачу; без декомпозиции доступ определяется ответственным самой задачи. Он создаёт подзадачи, обсуждает доступные задачи и отмечает свои чек-листы. Сроки и назначения существующих задач меняют руководитель и модератор. Каждая подзадача проходит приёмку, итоговая цель тоже закрывается приёмкой.

Дедлайн подзадачи не позже общего. Сократить общий срок за сроки открытых подзадач нельзя. Папки создаются, переименовываются, архивируются, восстанавливаются; удалить можно только пустую. Архив сохраняет задачи, доступные через «Все».

## До внешнего запуска

1. Проверить код, новые сценарии tests/architecture_v2.test.js и совместимость прежних тестов с новыми правами. Прежний результат тестирования не подтверждает эту версию.
2. Подтвердить допустимость Google Таблиц и Диска для рабочих данных и вложений. Ограничение доступа не заменяет согласование места хранения.
3. Проверить доставку писем от Google-аккаунта на @vtb.ru и доступ с рабочих устройств.
4. Сначала использовать отдельную пробную таблицу с условными данными.

## Настройка

1. Создать таблицу под аккаунтом владельца, доступ к самой таблице — только доверенным администраторам.
2. Через Расширения → Apps Script перенести семь файлов: Code.gs, Core.gs, Status.gs, Access.gs, Current.gs, CurrentMail.gs и appsscript.json.
3. Выполнить setup(). В существующей таблице он добавит в Users колонки subtype, preferences_json, session_expires.
4. Первого руководителя создать вручную в Users: уникальный id, name, handle, role=head, email на @vtb.ru, active=TRUE. Руководитель ровно один. key_hash, session_expires и last_read_ts вручную не заполнять.
5. Для остальных: role=owner, subtype=admin/commandant/inspector; либо role=mod, subtype=moderator. Адреса уникальны. После первого входа сотрудников можно добавлять и менять кнопкой «Сотрудники…». При редактировании рабочая почта подставляется из авторизованного справочника.
6. Проверить Settings.planner_url. mail_enabled отключает уведомления о задачах, но не коды входа.
7. seedDemo() — только для пробной таблицы. Он добавляет задачи, пользователей, чек-листы, события и папки. Для рабочего запуска использовать чистую таблицу. У старых демо-пользователей нет банковских адресов и новых subtype — их необходимо настроить явно.
8. Развернуть как веб-приложение: выполнять от имени владельца, доступ «Все». URL /exec вставить в const API_URL в planner.html.
9. Опубликовать planner.html и shared/*.js вместе. Существующий workflow также включает docs/demo_tasks.json. Access.gs требуется в Apps Script, на Pages не нужен.
10. При обновлении Apps Script выпустить новую версию существующего развёртывания. Открытие /exec проверяет только служебный ответ, а не вход и запись.

## Вход и вложения

Самостоятельной регистрации нет: код отправляется только активному пользователю из Users на @vtb.ru. Старые персональные ссылки отключены. Код — 6 цифр, 10 минут, максимум 5 попыток; повтор не чаще минуты, максимум 10 отправок на пользователя в сутки. Код и сеансовый ключ не записываются серверным кодом в журнал.

Сеанс — 7 дней. Новый вход заменяет предыдущий сеанс пользователя. Выход удаляет локальный ключ; серверный отзыв доступен через меню таблицы.

Вложения — до 3 файлов и 2 МБ суммарно: PDF, PNG, JPEG, TXT, CSV, DOCX, XLSX, PPTX. Встроенного антивирусного анализа нет. Папка «Планировщик — закрытые вложения» создаётся автоматически; её id хранится в Script Properties. Не предоставлять папке общий доступ. Скачивание проходит через API с проверкой участия в задаче. В демо вложения остаются в браузере, размер хранилища зависит от браузера.

При частичном сбое записи комментария могут остаться файлы без события в таблице. Автоматическая уборка таких файлов пока не реализована. Резервная копия таблицы не копирует папку вложений.

## Уведомления

В «Я — … → Настройки писем»: назначения, упоминания и возвраты включены по умолчанию; ежедневная сводка выключена. Сводка содержит свои незавершённые задачи с отметкой просрочки.

Меню таблицы включает резервное копирование, пересчёт статусов и сводку около 08:00 по Москве. Точное время триггера не гарантируется. Квоты почты и доставка в банковскую сеть требуют живой проверки.

## Приёмочная проверка

- Разные ответственные получают разные наборы целей; чужая цель недоступна прямым вызовом API. Коллеги внутри доступной цели видны.
- Руководитель и модератор принимают и возвращают каждую подзадачу самостоятельно.
- Ответственный создаёт подзадачи, но не меняет назначенные сроки. Дедлайн подзадачи ограничен общим сроком и при создании, и при переносе.
- Телефон: выпадающий список папок, «Только мои», полноэкранный таймлайн и выход из него.
- Неверный, просроченный и повторно использованный код; лимиты; отключение пользователя, отзыв и истечение сеанса.
- Вложения: форматы, размер, скачивание участником, отказ постороннему, сохранность после обновления страницы.
- Настройки сохраняются; выключенные события не отправляются; сводка приходит только подписавшимся и содержит только их задачи.
